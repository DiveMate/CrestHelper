## 0. 一句话定位

libdivecomputer 只告诉你「**电脑表当时是怎么判的**」（`DC_FIELD_DECOMODEL` → ZHL-16C + GF 30/85）。
你要做的是：**拿原始深度剖面，用别的算法/别的安全边界重算一遍，把「当时没报警但实际有风险」的地方挖出来。**

## 1. 减压算法引擎（`core/deco`）

### 1.1 统一抽象

```rust
pub trait DecoModel {
    fn id(&self) -> AlgorithmId;
    /// 逐秒推进组织负荷
    fn step(&mut self, t: Duration, depth_m: f64, gas: &GasMix) -> TissueState;
    /// 当前减压天花板（米），<=0 表示无需停留
    fn ceiling(&self) -> f64;
    /// 在某深度还能待多久（NDL，秒）；None = 已是减压潜水
    fn ndl(&self, depth_m: f64, gas: &GasMix) -> Option<u32>;
    /// 计算完整减压计划，返回停留表 + TTS
    fn plan(&self, ascent_rates: &AscentProfile) -> DecoSchedule;
    /// 若此刻直冲水面，会达到的梯度因子（GF99）
    fn gf99(&self, surface_pressure: f64) -> f64;
}
```

一条潜水 → 遍历 `(t, depth, gas)` 采样 → 每秒 `step()` → 同时记录 `ceiling/gf99/cns/otu` 时间序列。
这就是后续所有风险规则的**输入信号**。

### 1.2 要实现的算法

| 算法 | 难度 | 状态 | 说明 |
|---|---|---|---|
| **ZHL-16C + GF** | 低 | 主力，先做 | 16 组织，N₂/He 双半时；GF low/high 线性插值 |
| ZHL-16A / 16B | 低 | 顺带 | 只是半时表不同（A 用 4–635min，B 与 C 半时相同、a/b 不同） |
| ZHL-8 | 低 | 顺带 | 8 组织版本 |
| **VPM-B (+GFS)** | 高 | 二期 | 气泡模型，需要临界半径回归、GFS 保守度 |
| **RGBM（近似）** | 中 | 二期 | Suunto/Mares/Cressi 专有未公开，按 DiveComputerSimulator 的做法：ZHL-16C+GF 打底 + 惩罚项校准到公开值 |
| ZH-L16 ADT MB | 中 | 二期 | Scubapro「自适应」，需按微气泡假设加惩罚 |
| DCIEM | 中 | 二期 | 加拿大国防部模型，参数表需查文献 |

### 1.3 ZHL-16C 关键公式（实现时直接用）

**组织负荷积分（Schreiner / Haldane 指数形式）**

```
p_amb      = 1.0 + depth_m / 10.0        # bar（海水，10 m = 1 bar）
p_wv       = 0.0627                       # 肺泡水蒸气压 bar
p_inspired = (p_amb - p_wv) * f_gas       # f_gas 为该气体在混合气中的分数
p_tissue_new = p_inspired + (p_tissue - p_inspired) * exp(-Δt / τ)
τ = t_half / ln2                          # t_half 单位与 Δt 一致（秒）
```

16 个组织的半时（分钟，**N₂ / He**）：

```
N₂: 5.0 8.0 12.5 18.5 27.0 38.3 54.3 77.0 109.0 146.0 187.0 239.0 305.0 390.0 498.0 635.0
He: 1.88 3.02 4.72 6.99 10.21 14.48 20.53 29.11 41.20 55.19 70.69 90.34 115.29 147.42 188.24 240.03
```

**M 值线与梯度因子**

```
M(p_amb)  = a + p_amb / b                      # GF = 100% 的 M 值线
P_allowed = p_amb * (1 - GF + GF/b) + a * GF   # 施加 GF 后允许的组织压力
ceiling   = (P_tissue - a*GF) / (1 - GF + GF/b) # 反解出天花板环境压 → 换算成米
```

GF 的插值：`GF_low` 作用在**第一个停留深度**，`GF_high` 作用在**水面**，中间按深度线性插值。
（ZHL-16C 的 a/b 系数请用 Bühlmann 原表或 Baker 的表格核对一遍再落地。）

**GF99**（最有用的单一风险指标）

```
GF99 = (P_tissue_worst - p_surf) / (M(p_surf) - p_surf)
```

`GF99 > 100%` = 组织压力已越过 M 值线，理论上「这一刻直冲水面就会出事」。
把 GF99 沿时间画成曲线叠加在剖面图上，风险一目了然。

### 1.4 参考实现建议

**Subsurface 的 `core/deco.c` / `core/planner.c`（GPL-2.0）** 是现成的、经过 15 年实战检验的 ZHL-16 + VPM-B + GF 实现，也是目前最强的对照基准：
- 拿它做**数值对齐测试**：同一剖面喂进去，你的结果和它对不上就是你的 bug。
- ⚠️ GPL-2.0：读实现、做对拍没问题；直接复制代码会让你的项目也必须 GPL。
- 纯 Rust 的参考可看 `deco` / `buehlmann` 相关 crate，但成熟度不如 Subsurface。

**DiveComputerSimulator（AGPL-3.0）** 提供：
- `npm run calib`：按深度×GF 生成 NDL 表 → 拿来验证你的 NDL 计算。
- 它标注了 7 款「公开参数」电脑（Shearwater Perdix 2 / Peregrine TX、Garmin Mk3i、Suunto Nautic、Mares Quad Ci / Quad 2 / Genius）→ 可直接对齐具体机型的数值。
- 同样：参考思路可以，复制代码会传染 AGPL。

## 2. 风险规则引擎（`core/risk`）

每条规则是一个独立函数，输入「剖面 + 组织时间序列 + 气体序列 + 上下文（上次潜水、水面间隔）」，输出 `Vec<RiskFinding>`。做成**可插拔规则集**，用户可以开关和调阈值。

### A. 上升速率（最容易量化、也最常见的问题）

| ID | 规则 | 默认阈值 | 严重度 |
|---|---|---|---|
| `ASCENT_0_10M` | 最后 10 m 平均上升速率 | >10 m/min 警告；>18 m/min 严重 | 1/3 |
| `ASCENT_AVG` | 全程平均上升速率 > 9 m/min | | 1 |
| `ASCENT_ALARM` | 电脑表已上报 `SAMPLE_EVENT_ASCENT` | | 2 |
| `ASCENT_UNCONTROLLED` | 连续 10 秒速率 > 30 m/min（失控上升） | | 3 |

### B. 减压与组织负荷

| ID | 规则 | 说明 | 严重度 |
|---|---|---|---|
| `GF99_OVER` | 任一时刻 GF99 > 100% | 越过 M 值线 | 3 |
| `CEILING_VIOLATION` | 实际深度浅于减压天花板，累计 > 30 s | 明确了但没执行 | 3 |
| `MISSED_DECO_STOP` | 表提示强制减压停留但剖面无对应停留 | | 3 |
| `SHORT_DECO_STOP` | 实际停留 < 计算 TTS 的 80% | | 2 |
| `MISSED_SAFETY_STOP` | 最大深度 > 10 m 且未在 3–5 m 停留 ≥ 3 min | | 1 |
| `NDL_MARGIN` | 免减压潜水但 NDL 余量 < 5 min | 擦边 | 1 |
| `DEEP_STOP_MISS` | 表提示深停但未执行 | | 1 |

### C. 剖面形态

| ID | 规则 | 阈值 |
|---|---|---|
| `REVERSE_PROFILE` | 本次比上次深，且水面间隔 < 12 h | 反向剖面 |
| `YOYO` | 上升 > 10 m 后再次下潜 > 10 m | 反复升降 |
| `SAWTOOTH` | 升降切换次数 > 6 | 锯齿剖面 |
| `MULTILEVEL_INVERT` | 出现「先深后浅再深」的违反 multi-level 原则的段 | |

### D. 重复潜水

| ID | 规则 | 阈值 |
|---|---|---|
| `SHORT_SI_DEEP` | 水面间隔 < 60 min 且本次更深 | |
| `MANY_IN_24H` | 24 h 内 ≥ 4 次 | |
| `CONSECUTIVE_DAYS` | 连续 ≥ 5 天潜水且平均深度 > 18 m | 累积负荷 |

### E. 气体与氧中毒

| ID | 规则 | 阈值（NOAA 常用） |
|---|---|---|
| `PPO2_LIMIT` | ppO₂ > 1.4（减压段）/ > 1.6（工作段） | |
| `MOD_EXCEEDED` | 深度超过当前气体 MOD | |
| `CNS_HIGH` | 单次 CNS > 80%，或 24 h 累计 > 150% | |
| `OTU_HIGH` | 单日 OTU > 300，连续多日 > 850 | |
| `GAS_SWITCH_OFF_MOD` | 在 MOD 之上/之下不当深度切换气体 | |

### F. 环境与数据质量

| ID | 规则 |
|---|---|
| `COLD_WATER` | 最低水温低于用户设定阈值 |
| `THERMOCLINE` | 5 min 内降温 > 3 ℃（温跃层，常伴随浮力/配重失误） |
| `SAMPLES_MISSED` | 电脑表上报了采样丢失事件 |
| `DEPTH_SPIKE` | 相邻采样深度跳变 > 5 m 且非上升段（传感器异常） |

> 所有阈值写进设置页，按「保守 / 标准 / 激进」三档预设，也允许逐条改。

## 3. 日志合并：中途升水又下水

### 3.1 判定流程

```
1. 预处理
   - 深度序列做 3~5 点中值滤波，去掉传感器抖动
   - depth <= depth_surface (默认 0.5 m，可调 0.2~1.5) 视为「在水面」

2. 切段
   - 扫描出所有「水下段」（连续 depth > depth_surface 且时长 ≥ min_segment_time，默认 60 s）
   - 以及它们之间的「水面段」

3. 合并判定（对每一个水面间隔 SI）
   SI <  merge_threshold      (默认 10 min，可配 1~30)  → 合并为同一次潜水  (consecutive)
   SI <  repetitive_threshold (默认 12 h)               → 不合并，标记 repetitive
   否则                                                  → 独立单潜 (single)
```

阈值参考：DiveComputerSimulator 用的是 **<15 min = consecutive，<12 h = repetitive，否则 single**；不同厂商标准不一（有的 3 min、有的 10 min）。**做成可配置，默认 10 min**。

### 3.2 合并时的处理（关键：不是简单拼接）

| 字段 | 合并规则 |
|---|---|
| `start_utc` | 第一段入水时刻 |
| `duration_s` | 全段总时长（含水面段） |
| `bottom_time_s` | 各水下段时长之和（**不含**水面段） |
| `max_depth` | 各段最大值 |
| `avg_depth` | 按时间对深度加权平均（水面段按 0 m 计入） |
| `temp_min` / `temp_surface` | min / 第一段起点温度 |
| 剖面序列 | 段1 + [深度 0、时长 = SI 的水面段] + 段2 + ... |

**最重要的一点**：合并后重算减压时，**水面段要当作真实的水面间隔来积分**（组织在 0 m 继续排气），这样得到的才是「重复潜水的残余氮」模型。如果简单地把两段首尾相接当连续潜水算，会**低估**风险——这正是合并功能真正的价值所在。

### 3.3 工程细节

- `dive_segment` 表记录每一段（seq / 起止 / 最大深度 / 底部时间 / `source_dive_id`）。
- `dive.is_merged = 1`，保留原始未合并记录 → **合并可一键撤销**。
- 提供**手动合并 / 手动拆分**入口：自动判定不可能 100% 准（比如电脑表自己已经合并过、或水面停留时人在船上）。
- 边界处理：
  - 水面段 < `min_surface_gap`（默认 30 s）→ 视为波浪/贴水面游动造成的假出水，**不切段**。
  - 若电脑表固件本身已经把这类潜水合并成一条 → 用 `is_merged` 标记为 `device-merged`，避免二次合并。

## 4. 无效日志过滤

### 4.1 规则表（默认阈值，全部可配）

| ID | 规则 | 默认 |
|---|---|---|
| `F01_MIN_DEPTH` | 最大深度 < 2.0 m | 丢弃/标记 |
| `F02_MIN_DURATION` | 潜水时长 < 60 s | 丢弃/标记 |
| `F03_MIN_SAMPLES` | 有效采样数 < 20 | 丢弃/标记 |
| `F04_NEVER_SUBMERGED` | 从未在 1.5 m 以下停留 ≥ 60 s（入水即出、洗手、落水测试） | 丢弃 |
| `F05_FREEDIVE` | `DIVEMODE == FREEDIVE` 且用户勾选「只看水肺」 | 标记 |
| `F06_TRAINING` | 最大深度 < 5 m 且时长 < 15 min | **标记为 training**（泳池课），不丢弃 |
| `F07_DUPLICATE` | fingerprint 相同，或（起始时间 + 最大深度 + 时长）三元组相同 | 去重 |
| `F08_BAD_TIME` | 起始时间在未来，或早于 1980 | 丢弃 |
| `F09_BROKEN_SERIES` | 采样时间轴断裂 > 30 s 且未标注采样丢失 | 标记 |

### 4.2 策略

- **默认只标记，不删除**：结果落到 `dive.is_valid` + `invalid_reason`，UI 默认隐藏，可一键「显示被过滤项」并手工恢复。
- **`raw_blob` 永不删除**：过滤规则以后改了可以重跑。
- 过滤**先于**合并执行（先去掉垃圾，再判断要不要合并，否则噪声会污染切段）。
- 提供「重跑过滤」按钮：改完阈值对全库重新打标。

## 5. 报表体系

| 报表 | 内容 | 形态 |
|---|---|---|
| **单潜详情** | 剖面图（叠加 ceiling / GF99 / 温度 / 气体色带）+ 关键指标卡 + 风险清单 + 逐段统计 | 屏幕 + PDF |
| **日志汇总** | 按时间/潜点/潜伴/标签筛选：次数、总底部时间、累计最深、平均深度、最深、最长、温度区间 | 表格 + 图表 |
| **风险审计** | 按严重度排序的风险清单，支持按规则 ID 聚合统计「哪类问题我最常犯」 | 表格 |
| **算法对比** | 同一条潜水在多种算法/GF 下的：首个停留深度、TTS、GF99 峰值、ceiling 越界时长、是否免减压、CNS | 矩阵表 + 叠加曲线 |
| **趋势** | 月度/年度潜水次数、累计底部时间、平均深度、风险数的时间序列 | 折线/柱状 |
| **年度回顾** | 总次数、总时长、最深、最长、新潜点、风险改进对比 | 图文 PDF |

**导出**：PDF（自绘剖面图）、CSV/XLSX（明细）、**UDDF**（潜水日志通用 XML，可与 Subsurface 等其他软件互导）、JSON（全量备份/迁移）、`.divelog` 单文件包（SQLite + raw blob，供桌面↔安卓搬运）。

## 6. 「切换算法发现隐藏风险」的交互设计

这是整个分析模块最有价值的入口，建议做成潜水详情页的一个**固定侧栏**：

```
┌─ 减压算法 ──────────────────────┐
│ 基准：[表上设置 ZHL-16C GF 30/85 ▾] │
│ 对比：[GF 50/70 (保守)          ▾] │
│       [+ VPM-B] [+ ZHL-8] [+ RGBM≈] │
├──────────────────────────────────┤
│ 算法        首停  TTS  GF99  越界  │
│ 表上 30/85   —    —   87%    0s   │
│ GF 50/70    6m   8min 112%  45s ⚠ │
│ VPM-B       9m  14min  —    92s ⚠ │
│ ZHL-8       3m   5min  94%    0s   │
├──────────────────────────────────┤
│ ⚠ 用保守设置重算后，本次潜水存在    │
│   45 秒 ceiling 越界（t=23:10, 8m）│
│   → 查看剖面图高亮                 │
└──────────────────────────────────┘
```

典型「隐藏风险」场景：
- 表用 GF 30/85（激进）→ 免减压；换 GF 50/70 → 出现 8 min 强制减压义务。
- ZHL-16C 判定免减压 → VPM-B 出现减压义务（气泡模型对深停更敏感）。
- 单次潜水没问题，但**带上前一次的残余氮**（重复潜水）后 GF99 冲到 105%。
- 上升速率在 0–10 m 段超标，但电脑表没报警（阈值设得松）。

## 7. 落地顺序

1. **ZHL-16C + GF**（含 NDL / ceiling / TTS / GF99），先能算。
2. **对拍**：拿 Subsurface `deco.c` 或 DiveComputerSimulator 的 NDL 表校验数值。
3. **剖面预处理**（滤波、切段、水面段识别）→ 支撑合并与上升速率规则。
4. **规则引擎**：先上 A 类（上升速率）+ B 类（GF99 / ceiling 越界），这两个命中率最高、最直观。
5. **日志合并** + **无效过滤**（两者都要在导入管线里跑，且可重跑）。
6. **报表与导出**。
7. 二期再上 VPM-B / RGBM 近似 / DCIEM。

## 8. 单元测试基准（不依赖真实设备）

- 用 `tools/cr4_probe.py download` 抓下来的 `.bin` → `dc_parser_new2` 解析 → 存成 fixture。
- DiveComputerSimulator 的 `npm run calib` / `npm run scenario` 输出可作为 NDL 与停留行为的对拍基准。
- Subsurface 有 `tests/` 里的 dive plan 测试，可对拍 planner 结果。
- 关键回归点：ZHL-16C 的 NDL 表（空气，标准 GF）、GF 插值、ceiling 反解、TTS 迭代收敛。
